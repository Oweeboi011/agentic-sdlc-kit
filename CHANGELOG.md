# Changelog

All notable changes to this kit. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/).

## [Unreleased]

### Added

- `mcp/astral.json`: ASTRAL MCP (HTTP, read-only ASTRAL tools: projects, overview, agent health, feedback) for the `sre` and `feedback` agents. Set `ASTRAL_MCP_URL` (`https://<ASTRAL MCP host>/mcp`) and `ASTRAL_MCP_KEY` for Claude Code; Copilot reads them as `COPILOT_MCP_ASTRAL_MCP_URL` / `COPILOT_MCP_ASTRAL_MCP_KEY` secrets (url and headers now map like env).
- `sre.yml` / `feedback.yml`: optional secrets `astral-mcp-url` + `astral-mcp-key` (starter passes repo secrets `ASTRAL_MCP_URL` / `ASTRAL_MCP_KEY`); when both are set the agent gets the `astral` tools via `--mcp-config` (placeholders only, the key stays in env).
- Skeleton: README, licence, code owners, CI (ruff, pytest, actionlint), release workflow (moving major tag), `kit-sync` entry point.
- JSON Schemas for agent frontmatter, skill frontmatter and a project's `.github/astral-kit.yml` (`schemas/`). Agents are propose-only (`human_gate.mode: propose`); skill names follow the [Agent Skills spec](https://agentskills.io/specification).
- `kit-sync --validate [--kit DIR] [--project DIR]`: schema checks plus name/file match and references to skills, MCP servers and kit agents. Exits 1 on any problem. CI runs it on the kit.
- `kit-sync` renderer: agents, skills and instructions into the Copilot and Claude Code layouts, `AGENTS.md` and `.claude/CLAUDE.md`. Marker with sha256 per file, `--check` for drift, `<!-- project -->` sections preserved, stale files removed, project-owned files never overwritten. Golden tests in `tests/fixtures/`.
- Instruction frontmatter schema (`applyTo`, optional `stack`) and MCP template checks in `--validate`.
- Content (K4): 7 propose-only agents (`planner`, `coding`, `review`, `test`, `release`, `sre`, `feedback`; one per stage 1-6 and 8), 9 skills, 5 instructions (`general`, `python`, `typescript-react`, `bicep`, `adr`), 3 MCP templates (`github` and `azure` read-only, `playwright`; versions pinned). Content ships inside the wheel, so `pipx run` renders it.
- Copilot layout: built-in `github`/`playwright` MCP servers are referenced, not redefined; `${NAME}` secrets become `${{ secrets.COPILOT_MCP_NAME }}`. Trigger `repository_dispatch:<type>` added for alert-driven agents.
- Reusable workflows (K5), `on: workflow_call` only: `ci-python`, `ci-node`, `security` (gitleaks with checksum check, dependency review on PRs), `iac-validate` (Bicep build + lint), `deploy-aca` (OIDC, keeps running images across re-provisioning, rolls apps and jobs, smoke test), `e2e-playwright` (report on failure), `kit-drift` (`kit-sync --check` at the pinned version). The kit's CI runs `ci-python` and `security`.
- Agent workflows (K6), reusable and propose-only, on Claude Code Action v1.0.271 (pinned by SHA): `planner` (refinement comment on a `needs-refinement` Issue; read tools and `gh issue view|comment` only) and `claude-code` (draft PR from an `agent:claude` Issue on `agent/issue-<N>`; merge, review, ready and force-push denied; a guard step keeps the PR a draft; optional GitHub App token so CI runs on the PR). Anthropic API key or Microsoft Foundry over OIDC. Starter `agents.yml` wires the labels.
- Sample project (K8): `examples/sample-project/` with every runtime, stack, agent and template group, committed as rendered. Kit CI job `sample project (E1, E2)` installs the wheel, runs `kit-sync --check` on it and expects a hand edit in a copy to fail; `actionlint` (E3) also covers the sample's starter workflows.
- Templates (K7): issue forms (`story`, `bug`, `decision` for `needs-decision`, `feedback`), PR template (requirement IDs, project gate; project checklist below `<!-- project -->`) and `.githooks/commit-msg` are rendered with the marker and drift-checked; groups set by optional `templates` in `astral-kit.yml`. `#` markers for YAML and scripts, after a shebang. `kit-sync --init` writes starters once (CODEOWNERS, `dependabot.yml`, a CI caller of the reusable workflows, `copilot-setup-steps.yml`).
- Policies (K7): `ruleset-main.json` (default branch: no deletion or force push, code owner review, last-push approval, squash, CodeQL), `environments.json` (dev, staging, prod from `main`; prod reviewers), `labels.json` (every agent trigger label), with `gh api` apply commands in the README.
- Spec Kit preset (K7, ADR-0024): `presets/spec-kit/` for Spec Kit `~=1.4.0` appends NFR, security, data-handling and traceability sections to the spec and replaces the constitution template with one generated from `instructions/`; releases attach `spec-kit-preset.zip`.
- Agent evidence contract (ADR-0026): required `evidence` (`kind`, `label`, `trigger`) in agent frontmatter, checked against the triggers; labels `agent:planner`, `agent:review`, `agent:release`, `agent:sre`, `agent:feedback`. Composite action `.github/actions/agent-evidence` appends `<!-- agentic-sdlc-kit agent= kit= run= model= -->` to the bot-authored output of the run, labels PRs and Issues, writes the step summary and outputs `count`, `evidence-url`; every agent workflow runs it `if: always()`.
- Agent workflows for the other 5 agents, propose-only: `review` (one verdict + ranked findings comment, no PR code run), `test` (draft PR on `agent/tests-<N>`, guard fails on non-test files), `sre` (incident Issue from an `alert` dispatch, triage comment with KQL), `feedback` (weekly, at most 5 `from-feedback` Issues, guard closes extras), `release-agent` (draft release only, guard re-drafts). Starter `agents.yml` wires all 7.
- Canary (ADR-0026): golden tasks `canary/tasks/*.yml` for planner, review, coding, test, SRE and feedback; `kit-canary seed|grade|cleanup` with deterministic graders; reusable `canary` workflow (jobs `grade (<agent>)`, artifacts `canary-results-<agent>.json`) and `canary/caller.yml` for the canary repo. `Release` requires a passing canary on the tagged commit when `vars.CANARY_REPO` is set.
